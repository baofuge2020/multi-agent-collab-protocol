# 多智能体协作协议（Multi-Agent Collaboration Protocol）

分享一套我自己跑通的多智能体协作协议，纯经验，无推广。

> 想先看踩坑全过程？读这篇实战复盘：[两个 AI agent 互相收不到消息怎么办](ARTICLE.md)。

背景：本地 coordinator + 多台远程 executor，靠文件消息队列通信。

踩过的坑和对应规则：

1. bot 之间聊天收不到 → 改文件队列，一个 inbox 文件 = 一个 turn
2. 空输出误判为成功 → 远端返回带 sentinel，本地校验后才认
3. 重试风暴 → 退避到分钟级，快重试会堆积半开连接
4. socket 通但握手卡住 → 是链路丢大包，不是主机挂了，别瞎重启

整理成了一份完整协议包（4 协议 + 11 坑 + 3 模板），免费自取，欢迎拍砖。

---

## 这份协议解决什么

多智能体系统出问题时，九成不是模型不行，是协作规则没定好：消息丢了、重试把连接堵死、空结果被当成成功、成本悄悄失控。工具谁都能装，值钱的是把「怎么做」拆好的规则。

## 四条协议速览

| 协议 | 一句话规则 |
|---|---|
| 通信 | 一个 inbox 文件 = 一个 turn，多个问题编号塞进同一封信，300 字内，不客套 |
| 分工 | 远端只做必须在那台机器上发生的事；判断、分析、决策全归本地协调端 |
| 成本 | 执行端用便宜模型，推理留给协调端；批量操作合并到一次连接 |
| 容错 | 慢退避（分钟级）；socket + 握手对照区分主机故障与链路故障；每个远端返回带结束哨兵 |

## 怎么用

1. 把整个目录装到 AI 助手的 skills 目录（WorkBuddy 用户放到 `~/.workbuddy/skills/`）。
2. 让助手阅读 `SKILL.md`，它会在设计、搭建或排查多智能体协作时自动加载对应协议。
3. 用 `assets/` 的模板落地：先写角色卡，再定消息队列，建立哨兵标记，跑通一轮双向通信。
